# OmniRoute — Claude Code plugin marketplace

This repository doubles as a **Claude Code plugin marketplace**. The catalog lives in
[`.claude-plugin/marketplace.json`](../.claude-plugin/marketplace.json); each entry points at a
self-contained plugin directory below.

## Install

```bash
# 1. register the marketplace (once)
/plugin marketplace add wallan-a11y/OmniRoute

# 2. install what you need
/plugin install omniroute-api@omniroute
/plugin install omniroute-cli@omniroute
/plugin install omniroute-mcp@omniroute
```

Working from a local clone instead:

```bash
/plugin marketplace add /path/to/OmniRoute
```

Refresh after the repo changes with `/plugin marketplace update omniroute`.

## Plugins

| Plugin          | Payload                                 | What it gives Claude                                                                                                                                                 |
| --------------- | --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `omniroute-api` | 23 skills (`omni-*`)                    | Drive a running OmniRoute over its OpenAI-compatible REST API: providers, models, combos & routing, keys, budget, cache, compression, resilience, tunnels, webhooks. |
| `omniroute-cli` | 22 skills (`cli-*`, `config-codex-cli`) | Drive the `omniroute` command-line tool: serve, health, chat, routing, evals, batches, backup, policy, setup, Codex CLI wiring.                                      |
| `omniroute-mcp` | `.mcp.json` (stdio)                     | Registers the built-in OmniRoute MCP server (`omniroute --mcp`) as an MCP server in Claude Code.                                                                     |

`omniroute-mcp` ships with `defaultEnabled: false` because it spawns the `omniroute` binary. Install
the CLI first (`npm install -g omniroute`), then enable the plugin.

## Layout

```
.claude-plugin/marketplace.json     ← catalog (marketplace root = repo root)
plugins/
  omniroute-api/
    .claude-plugin/plugin.json
    skills/<id>/SKILL.md            ← mirrored from ../../skills/
  omniroute-cli/
    .claude-plugin/plugin.json
    skills/<id>/SKILL.md
  omniroute-mcp/
    .claude-plugin/plugin.json
    .mcp.json
```

## Keeping the payload in sync

`skills/` at the repo root stays the **single source of truth** — it is generated by
[`scripts/skills/generate-agent-skills.mjs`](../scripts/skills/generate-agent-skills.mjs). The plugin
payloads are copies published by:

```bash
npm run sync:plugin-skills    # write plugins/*/skills from skills/, stamp the version
npm run check:plugin-skills   # verify only — exits 1 on drift
```

The same command stamps `package.json`'s `version` into every `plugin.json`. Claude Code pins an
installed plugin to that string, so a release that ships new skills without bumping it would never
reach users — `check:plugin-skills` fails on that mismatch too.

Routing lives in `PLUGIN_ROUTES` inside
[`scripts/skills/sync-plugin-skills.mjs`](../scripts/skills/sync-plugin-skills.mjs). A new skill that
matches no rule makes the sync **fail** rather than being silently dropped from the marketplace.

The copies are deliberate, not incidental:

- tracked symlinks are rejected by `check:tracked-artifacts`, and a symlink would break anyway once
  Claude Code copies the plugin into `~/.claude/plugins/cache`;
- a marketplace entry with `"source": "./"` would copy the entire tracked tree (~217 MB) into that
  cache, once per plugin and per version — the plugin directories here are under 300 KB each.

Both invariants are enforced by
[`tests/unit/build/claude-plugin-manifests.test.ts`](../tests/unit/build/claude-plugin-manifests.test.ts).
